## 1. Scope and hypotheses

- Stage 1 compares **R**, the return objective below, against **R+D**, that identical objective plus DR², on **both** menus. The old fixed-risk ENB ladder is a descriptive reference only; neither arm may optimize it and relabel its output as return optimization.
- Stage 2 adds **R+E**, the same return objective plus ENB, only after C8 records a demonstrable DR² benefit meeting the predeclared gate in §7. No benefit, mixed/inconclusive results, insufficient power or an inactive bonus require **skipping ENB**; there is no separate-reason exception. This is the owner's computational stopping policy, not proof that DR² and ENB are mathematically equivalent or cannot ever add different value. Label skipped ENB **unevaluated**, not ineffective.
- Start with History replay. Pure replay functions exist in main; numerical GARCH functions exist in the integration run, but their existence does not establish qualification. The common return optimizer and rolling harness are absent. GARCH needs a later separately locked replication using its real engine; do not mix it into this replay comparison or substitute a normal approximation.
- The experiment is offline and needs no API/UI changes. Phase 1 remains the next deployment milestone; this experiment neither completes that checkpoint nor commits the project to paired optimizer publication, selector controls or engine-independent holdings. C8 decides the eventual delivery scope and reconciles affected assertions explicitly.
- Main hypotheses: DR² can improve conditional return outcomes or stability without material return harm; it can instead add no measurable value or create undesirable sacrifices. All are admissible results. No global optimum, universal diversification benefit or monotonic safer-direction control is assumed.

## 2. Proposed preference and materiality contract

Use unrounded annual simple returns in decimal units: `B=q(.025)`, `T=q(.50)`, `G=q(.975)`, with linear quantiles. One basis point (bp) is `0.0001`; one percentage point (pp) is `0.01`. Typical is the median, not the expected mean. Report mean separately.

**Return utility:** `U(w)=0.60 B(w)+0.30 T(w)+0.10 G(w)`. The same one-bp increase has strictly descending importance B, T, G. Locally, a one-bp Bad sacrifice requires more than two bp Typical or six bp Good to improve U. This is a finite tradeoff, not strict lexicographic maximization. For the owner's A `[-.05,.04,.12]` and B `[-.0501,.08,.18]`, `U(B)-U(A)=.01794` (1.794 pp), so B wins. There is no kink or stopping point at Bad = 0.

**Secondary score:** calculate `DR²=(sum_i w_i sigma_i)^2/(w' Sigma w)` from the origin's training covariance; `d(M)=clip(log2(M),0,4)`. R maximizes U; R+D maximizes `U+0.001 d(DR²)`. Thus doubling DR² is worth ten bp of U before the guard below, and the total bonus is bounded at 40 bp. Unlike normalization by the highest score found in a search, this scale cannot change when the candidate pool changes. A move from DR² 1 to 1.4 contributes about 4.85 bp U, large enough to affect near-ties. Stage 2 substitutes `M=ENB` calculated by the existing minimum-torsion definition; disclose its known correlated-menu inflation and the saturation at M = 16.

The financial feasible set is identical in every arm (§3). After searches, construct the same union candidate pool for all arms (§5), remove candidates dominated on all three return quantiles, and identify its maximum-U member `w_R`. A candidate dominates another only when **no return quantile is lower at all** and at least one is higher by more than `1e-10`; this strict partial order prevents tolerance-induced cycles. Dominance uses the optimization bank only, not statistical significance or independent evaluation; `1e-10` is numerical resolution, not economic materiality. Apply the following **common final preference-admissibility rule** relative to `w_R` before ranking either arm:

| Allowed sacrifice versus w_R | Proposed maximum |
|---|---:|
| Bad | 10 bp |
| Typical | 25 bp |
| Good | 50 bp |
| U | 2.5 bp |
| Both Bad and Typical lower by more than `1e-10` | Never admissible |

`w_R` always passes. R+D selects the admissible candidate with highest augmented utility; R retains maximum U. These guards are an explicit part of the proposed preference, not a new risk/cap constraint or a claim that DR² itself improves returns. They prevent diversification alone buying deterioration in both Bad and Typical. Report which guard binds, every accepted sacrifice and the unconstrained augmented-score winner. For each ranking, first compute its global maximum score, then form the tie set within `1e-12` of that maximum; select by higher B, then T, G, then lexicographically smaller weight vector in fixed menu order. Apply this once to U for the anchor/R and once to augmented utility for R+D; never use pairwise approximate-tie comparisons. The guards apply identically to R+E if authorized.

Positive return weights and Pareto filtering prefer simultaneous B/T/G improvements when the search finds them. A feasible candidate improving all four outcomes beats the incumbent; failure to find one does not prove impossibility. These numerical proposals need independent and later owner/Claude review: the owner's accepted example does not identify unique coefficients, diversification strength or materiality limits.

## 5. Reproducible broad search and local refinement

Use existing NumPy/SciPy/CVXPY/Clarabel dependencies only, with exact versions recorded and BLAS restricted to one thread. No new dependency is authorized. Proposed algorithm:

1. For each `(menu,origin,ceiling,replicate)`, create one 2,000 × 252 stationary replay index bank, mean block length 21, shared by all candidate evaluations and arms. Recenter each portfolio's historical daily returns on `mu_s'w/252` exactly as production; retain production's unscaled sample volatility and linear percentiles. Use the count-matrix identity for speed, validated against explicit daily compounding. Do not replace the objective with mean-minus-volatility, Gaussian quantiles or an annual buy-and-hold surrogate.
2. Use five complete optimization replicates, path seeds `20261013..20261017`. Candidate generator seeds are the corresponding seed plus `1_000_000`. Initialize a new seeded generator in each cell; identical seeds deliberately provide common random numbers across arms. Record the full generated matrices' hashes. **Primary conditional-policy return statistics and realized comparisons use optimizer seed `20261013` only.** The other four optimizer seeds are stability replications and per-seed diagnostics, never extra historical N, pooled policy-return observations or opportunities to choose a better policy.
3. Shared anchors: minimum variance, feasible cap-projected equal weight, and expected-return maximizers at X(.25), X(.50), X(1), restricted to ceilings at/below the current X. Retain duplicate attempts in the budget ledger, but cache duplicate evaluations. The legacy ENB ladder is never a search seed or optimizer substitute.
4. Generate 1,024 scrambled Sobol points in dimension `N+1` using a complete power-of-two draw. For even row indices, transform first N coordinates by `-log(clip(u,2^-53,1-2^-53))`, normalize, and Euclidean-project to the capped simplex. For odd rows, greedily fill the caps in descending coordinate order, ties by fund order, producing sparse boundary candidates. For each row, mix its candidate toward `w_min` by the last coordinate's square root; if risk exceeds X, move along the segment toward `w_min` by 60 bisection steps until feasible. Capped-simplex projection solves `sum clip(z_i-lambda,0,cap_i)=1` by 80 bisection steps, bracket `[min(z)-1,max(z)]`. Reject failed feasibility rather than normalize a violation away. These transformed points provide broad interior/boundary coverage; they are not a uniform feasible-set sample or a global-optimality certificate. [SciPy's Sobol documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.qmc.Sobol.html) motivates the complete power-of-two draw.
5. Select six shared local starts from the broad pool by descending U, greedily retaining starts at L1 distance >= .10 from every already selected start; if fewer than six qualify, fill from the remaining U order. If fewer than six distinct weights exist, repeat starts with separately recorded budgets. Each arm refines those same starts with its own objective, using COBYLA in N-1 coordinates with the final weight `1-sum(first N-1)`, all bounds and the risk inequality explicit, `rhobeg=.05`, `tol=1e-5`, `catol=1e-8`, `maxiter=384`. An external counter limits **all objective calls**, including infeasible/repeated calls, to 384 per start. Every candidate crossing a bound, sum or risk feasibility check by more than `1e-8` receives a deterministic penalty `1e6+1e6*sum(positive constraint violations)` and cannot enter the feasible pool. Define actual recentered replay growth `g_t=1+r_t'w-mean_s(r_s'w)+(mu_s'w)/252`, with the mean over training rows. Any `g_t<=0` receives the same base `1e6` minimization penalty, is excluded from the feasible archive, and retains the named `nonpositive_daily_growth` status, date and weights; do not clip it. Raw-input validity is a separate data check, not a substitute for this recentered-growth check. Invalid proposals count toward the call cap and invalid-proposal rate, not as whole-arm failures. SciPy documents `maxiter` as COBYLA's function-evaluation cap and warns that its trust-region tolerance is not an accuracy guarantee. [COBYLA reference](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-cobyla.html)
6. Broad proposals (1,024 plus at most five anchors) and local budgets (six × 384 = 2,304 calls **per arm**) are identical across arms. Quantiles change nonsmoothly when path rankings change; local refinement is a bounded heuristic. Record solver status, feasible evaluations and best-score trace even if the solver reports success. Never grant a losing arm extra starts or tune tolerances after seeing comparisons.
7. Union the feasible broad and both arms' local candidates, rescore each using the same cached return vector and covariance, then apply §2's dominance, anchor, guards and ranking. This gives both arms equal access to discoveries and prevents claiming a DR² benefit caused merely by a worse return-only search. Report native-search selections as diagnostics, final union selections as the primary comparison, and the shared versus arm-specific work separately. The union protocol is a research comparison, not a measured production architecture. If Stage 2 is later authorized, use the same per-arm budgets for all three arms and a three-arm union; preserve the original Stage-1 verdict and label any changed R/DR selections as Stage-2 pool-enrichment effects.
8. Lock selected weights before examining any independent draws or realized returns. Evaluate each optimizer seed's fixed selections on five **new** replay banks with seeds `20261113..20261117`, 2,000 paths each. For primary optimizer seed `20261013`, compute primary test quantiles from its pooled 10,000 annual outcomes; retain separate bank-level and optimizer-seed diagnostics. Never pool outcomes across optimizer seeds into the primary policy statistic. These draws test selection sensitivity conditional on the same historical sample/model; they are not new market history or realized out-of-sample returns. Do not replace a selected portfolio with one chosen from this test bank.

**Failure taxonomy and denominator:** evaluation-budget exhaustion with a valid feasible archive is normal bounded-search completion. A failed local start (solver returns non-success and no usable refinement) is recorded separately; other starts and the unchanged valid broad archive remain available. Ordinary invalid proposals receive the stated penalty, consume calls and retain raw statuses; they are not failed starts or arms. A failed arm is an inability to emit a valid final selection from that archive or a named computational error in its required evaluation. Verify `w_min` is feasible and has `g_t>0` for every recentered training row before searches; its retained archive entry guarantees an admissible maximum-U anchor unless a true input/computation error occurs. Handle COBYLA's returned non-success/evaluation-cap statuses explicitly and catch only a dedicated objective-call-budget sentinel; unexpected exceptions propagate as run errors, never become ordinary penalties or success statuses. Resource breaches are stop signals, not recoverable solver conditions. Preserve raw solver statuses, exception details and all attempted calls.

Freeze the denominator before search: actual distinct scheduled `(menu, common training-eligible origin, distinct ceiling, optimizer replicate)` cells, five replicates per cell; collapsed ceiling aliases count once here (retain their weights for §6 aggregation). A paired cell fails if **any required arm** fails; numerator is failed paired cells, denominator is all such scheduled cells, including failed/unattempted cells, never starts, calls or only survivors. Report failed starts separately and mark unattempted cells incomplete, not successful. Do not drop failed cells to compute a winning statistic; any unresolved failed/unattempted arm prevents a completed verdict, and a paired-cell failure rate >1% blocks success. Resource-ceiling breaches immediately stop the run as incomplete regardless of this rate.

Common exact-weight invariance is mandatory: same input sample, moments, weights and index bank produce identical outcomes, regardless of arm label or search route. The latest saved TSP sample must reproduce investigation digest `d6f782a9947c0fad3a8b85f0ff6906160eff4b1e7a9c2de8e270ccd4eeeba24e` and its recorded ranges before the harness is trusted; a mismatch blocks the run pending a documented provenance explanation.

## 6. Measurements and dependence-aware evidence

For every selected portfolio, retain training and independent-bank B/T/G, U, expected mean, annual path mean, loss probability, annual-loss-beyond-20% probability, raw DR², ENB only if Stage 2 is authorized, risk, cap/sum residuals, active guards, and exact weights. Report whether all three returns improve, whether all four improve, and each signed sacrifice; a bigger diversification number is never the benefit verdict by itself.

Realized evidence uses each origin's actual following 252 daily returns: annual return, loss indicator, return below -20%, worst daily return, annual maximum drawdown and realized annualized daily volatility. Report per-arm empirical q(.025)/q(.50)/q(.975) across origins and their U, plus paired annual-return differences, loss rates and drawdowns. There is **one realized annual return per origin**, not a realized q(.025) at every origin. Monthly cohorts overlap heavily; risk ceilings and menus also share outcomes. Neither those cells nor simulated paths are independent historical replications.

Calibration is separate: for each q in {.025,.50,.975}, report `1[y<=forecast_q]`, nominal versus empirical coverage, and pinball loss `(q-1[y<forecast_q])*(y-forecast_q)`. It assesses forecasts of each selected portfolio, while policy-performance comparisons use actual returns/drawdowns above. Lower pinball loss for a near-cash allocation does not establish a better portfolio: changing holdings changes the target distribution. Do not select R+D because its calibration loss is smaller. Proper scoring concerns forecast honesty, not the owner's utility. [Gneiting and Raftery (2007)](https://doi.org/10.1198/016214506000001437)

Stability: compute once across the five optimizer seeds for each menu/origin/ceiling (not once as a vote per test bank); report median and 90th-percentile pairwise weight L1 distances, standard deviation across optimizer seeds of each seed's pooled-test B/T/G and U, selection/guard frequencies, and adjacent-origin target turnover `0.5*L1(w_t-w_previous)`. Also evaluate fixed primary weights on each independent bank to separate Monte Carlo variation from reoptimization. Adjacent-origin turnover is a policy-change diagnostic, not frictionless-rebalancing trading volume.

Aggregate in this fixed order: first equal weight the three prescribed risk cells within an origin, then equal weight origins within a menu, then average the two menu summaries 50/50. Keep each menu/risk table visible; aggregate success cannot mask a failing menu or risk cell. For nonlinear metrics, compute quantiles within each menu/risk cell across its origin returns before averaging the resulting contrasts. Do not concatenate the larger TSP panel or all simulated paths into a claimed larger historical sample.

Use a paired circular moving-block bootstrap over the chronological **monthly origin index**, block length 24 origins, 2,000 resamples, seed `20261201`; sample identical index blocks for every arm, risk cell and menu and recompute the complete statistic. Report percentile intervals, disjoint-interval counts, calendar span, missingness and sensitivity to lengths 12 and 36. These intervals remain exploratory with fewer than 20 disjoint annual intervals; block resampling cannot create missing regimes or independence. Do not use IID t-tests, binomial intervals based on overlapping months, or label bootstrap resamples additional evidence.

Tail-power rule: empirical 2.5% quantiles with fewer than 200 disjoint annual intervals have fewer than five expected tail observations. This proposed floor is a warning threshold, not a guarantee of precision even above it. Below it, mark realized q(.025) superiority/calibration **underpowered**, display raw outcomes and ranges of plausible effects, and prohibit a confirmed real-world tail-benefit claim. The present Example history makes that limitation unavoidable; even the full TSP history is modest.

## 7. Predeclared criteria, sensitivity and stop rules

All thresholds here are proposed for review. Distinguish **valid experiment**, **positive conditional-model evidence**, **realized policy support**, **did not meet observed conditional screening criteria**, **material harm**, and **inconclusive historical evidence**. Return contrasts and meaningful-score-change statistics below use the primary optimizer seed and §6 aggregation; stability uses all five optimizer seeds.

| Dimension | Predeclared criterion, assessed separately for both menus |
|---|---|
| Independent replay return gain | Primary-seed pooled-test mean paired ΔU >= 5 bp; mean paired ΔB >= -5 bp, ΔT >= -10 bp, ΔG >= -20 bp; no risk cell has mean ΔU < -2.5 bp; additionally positive mean paired ΔU in >=4/5 separate test banks |
| Stable gain alternative | If primary-seed pooled mean paired ΔU is <5 bp, require mean ΔU >= -2.5 bp, the same ΔB/ΔT/ΔG and risk-cell ΔU floors; require those floors also in >=4/5 test banks. Once across the five optimizer seeds, require >=20% reduction in median pairwise weight L1 distance, absolute reduction >= .02, and no worsening of 90th-percentile L1 distance |
| Meaningful score change | Mean raw DR² gain >= .10 and R+D differs from R by L1 >= .02 in at least 20% of cells; otherwise report tested bonus inactive/near-inactive, not a general negative result about DR² |
| General stability | For each risk cell: across-optimizer-seed pooled-test Bad SD <= .10 × primary portfolio chart volatility in >=95% of origins; median pairwise weight L1 <= .20, 90th percentile <= .40; adjacent-origin target turnover median no more than R + .05 |
| Realized guardrails | Each risk cell: annual-return median loss <=25 bp, mean annual-return loss <=25 bp, loss-frequency increase <=5 pp, mean maximum-drawdown worsening <=1 pp; report every violation and paired uncertainty |
| Realized benefit support | Mean paired realized annual-return gain >=25 bp with dependence-aware 99% interval lower bound >0, **or** mean maximum-drawdown improvement >=1 pp with its 99% improvement interval lower bound >0 and mean annual-return loss <=25 bp; require >=20 disjoint annual intervals, all realized guardrails, and disclose the separate tail-power gate |
| Cost | Warm arm-search wall-time p95 R <=10 s TSP / <=30 s Example per scheduled cell; p95 of paired ratios `wall(R+D,c)/wall(R,c)` <=1.25 in each menu. Use linear quantiles; report medians, p95s, every paired ratio and failed-call costs under the timing contract below |

“Positive conditional-model evidence” requires, in **both** menus, either the replay-return branch (pooled primary-seed thresholds plus >=4/5 banks with positive ΔU) or the stability branch (primary-seed pooled and >=4/5 bank return floors plus the single across-optimizer-seed stability comparison), together with meaningful score change, general stability and cost. Test banks cannot provide independent votes on weight stability, because selected weights are fixed before bank evaluation. It cannot be called realized benefit. A **confirmed worthwhile benefit** additionally requires realized benefit support in both menus and no material harmed risk cell; only that stronger result qualifies as demonstrable DR² benefit for the ENB gate. **The frozen Example history cannot reach 20 disjoint annual intervals, so ENB cannot qualify on the current primary data and must be skipped.** This screening study can reject a costly/unstable preference, identify a promising model-conditional change and describe realized tradeoffs; real-world confirmation remains **inconclusive** even with positive modeled evidence. The confirmation threshold is a future-evidence standard, not a pass this dataset can achieve. A later owner/Claude review may reconsider the proposed gate before execution; there is no independent C8 exception or permission to lower a threshold merely to create an ENB path.

The support rule uses 99% intervals for its four predeclared menu × endpoint comparisons (two menus, return/drawdown); other reported intervals are descriptive 95%. This conservative multiplicity allowance does not cure short histories or block-bootstrap approximation error. Risk-cell guardrails remain mandatory, rather than additional endpoints from which to select a favorable result.

A valid completed comparison that fails the branch criteria is labeled **“did not meet observed conditional screening criteria”**, with every threshold result shown; it does not establish “no worthwhile benefit,” equivalence or a negative historical effect. Historical inference remains inconclusive unless its actual evidence criteria are met; no equivalence conclusion is authorized by default. “Material harm” is any breach of the realized point-estimate guardrails or independent-replay return floors; report it with uncertainty and its menu/risk location, without inferring universal harm. Unexplained data defects, failed invariance, incomplete paired arms, optimization feasibility failures, inadequate coverage or exhausted resource ceilings yield **inconclusive/invalid**, never a winner. Apply the failed-start/failed-arm/paired-cell taxonomy and frozen denominator in §5; raw failures and incomplete cells remain in the report. All nonqualifying DR² outcomes require skipping ENB under the owner's stopping policy.

Prespecified diagnostic sensitivities: use six common training-eligible origins at indices `floor(j*(K-1)/5)`, j=0..5, K the scheduled-origin count, all risk cells and both menus, primary optimization seed only. Independently change (a) DR² coefficient to .0005 and .002; (b) U coefficients to (.70,.20,.10) and (.50,.35,.15); (c) training lookback to 252 union-calendar rows, same origins and >=90% completeness; (d) double broad proposals to 2,048 and local caps to 768. All other rules and test banks stay fixed. For replay-return diagnostics, assess the same pooled gain/floors and >=4/5-bank positive-ΔU criteria on the six-origin subset. For stability-branch diagnostics, assess only the primary-seed pooled and >=4/5-bank return floors; cross-seed stability is **unavailable**, so these diagnostics cannot pass or independently validate the stability branch.
